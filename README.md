# bMuisc

基于 B站视频内容的跨平台音乐播放器：以听音频为主，也能随时打开视频，继续观看当前内容。

> **当前状态**：M0 媒体可行性验证完成；Windows 桌面端（Tauri 2）最小播放器已可用——解析链接、音频播放、队列管理、本地持久化（重启恢复队列与进度）均已实机跑通。音视频切换计划与账号登录一起实现（见[当前进度](#当前进度)）。

## 产品定位

让 B 站的音乐现场、演唱会、翻唱和音乐合集拥有方便的听歌体验。用户添加自己有权访问的视频后，可以连续听音频，也可以在同一播放进度切换到视频画面。

核心原则：

- **听歌优先**：默认展示封面、标题、UP 主和播放控制，减少画面对注意力的占用。
- **随时观看**：展开或收起视频时，保持当前曲目、进度和播放状态。
- **队列统一**：音频和视频模式共用播放队列、循环模式和收藏记录。
- **来源清楚**：保留视频来源、作者信息和跳转到 B 站原页面的入口。

## 平台范围

使用 **Tauri 2** 构建跨平台应用，共享前端界面和可复用的 Rust 逻辑。

| 平台 | 计划 |
| --- | --- |
| Windows | 首个开发与验证平台 |
| macOS / Linux | 核心播放流程稳定后进行适配和验证 |
| Android / iOS | 后续评估，复用界面和业务逻辑，按需实现原生能力 |

Tauri 支持多个平台，但 WebView 的媒体格式支持、后台播放、系统媒体控制和权限机制存在差异。移动端不作为第一版交付目标，各平台需要分别构建和测试。

## 第一版范围

先完成一条完整路径：**粘贴视频链接或 BV 号 → 选择分 P → 加入队列 → 播放音频 → 在当前进度切换视频**。

### 内容添加

- 接受常见 B 站视频链接和 BV 号，校验输入并读取可用的视频元信息。
- 展示标题、封面、UP 主、时长及分 P 列表。
- 多分 P 视频允许添加单个分 P 或全部分 P，每个分 P 对应一条队列记录。
- 内容不可用、需要登录或访问受限时，提供明确提示和打开原页面的入口。

### 播放控制

- 播放 / 暂停、上一首 / 下一首、拖动进度、音量调节。
- 顺序播放、单曲循环、列表循环、随机播放。
- 队列添加、移除、清空及调整顺序。
- 音频模式与视频模式切换，保留进度、音量和播放状态。
- 播放出错时允许重试或跳过，避免无限重试。

### 本地记录

- 保存播放队列、最近播放记录、音量和循环模式。
- 重启后恢复队列和上次进度，由用户触发继续播放。
- 使用稳定的视频标识保存记录，不把临时媒体地址作为持久数据。

### 后续功能

- 本地歌单与收藏管理。
- 内容搜索、收藏夹导入及必要的账号能力，先确认接口和授权方式的可行性。
- 系统媒体控制、媒体快捷键、托盘与桌面端后台播放。
- 移动端后台播放、锁屏控制和音频焦点管理。
- 歌词与章节信息，前提是有可用且允许使用的数据来源。

首版暂不包含离线下载、媒体转存、云端同步、推荐系统和会员内容能力。

## 界面规划

- **主区域**：初期展示添加入口、当前播放信息和队列；后续增加歌单与最近播放页面。
- **底部播放栏**：封面、标题、播放控制、进度条、音量、循环模式和视频开关。
- **视频区域**：按需展开，支持全屏；收起后回到音频模式。
- **状态反馈**：清楚区分正在解析、正在缓冲、需要登录、内容失效和播放失败。

## 技术方案

| 层级 | 技术选择 | 职责 |
| --- | --- | --- |
| 应用容器 | Tauri 2 | 窗口、权限、平台集成和应用打包 |
| 前端 | React + TypeScript + Vite | 界面、交互和页面组织 |
| 状态管理 | Zustand | 播放状态、队列与界面状态 |
| 原生逻辑 | Rust + Tauri Commands | 内容源访问、媒体地址解析和受控的本地能力 |
| 播放层 | HTMLMediaElement，必要时接入 MSE 播放方案 | 媒体加载、播放、定位和音视频同步 |
| 本地存储 | Tauri Store | 初期保存设置、队列和播放记录 |

如果后续歌单和历史记录规模增长，再评估 SQLite。首版以本地应用为主，不部署自有媒体服务。

### 模块边界

1. **内容源适配器**：输入视频标识，返回元信息、分 P 和当前可用的媒体信息；隔离平台接口变化。
2. **播放控制器**：统一管理播放状态、进度、队列、模式切换和失败恢复。
3. **媒体引擎**：负责具体媒体加载与同步，通过统一接口向播放控制器报告事件。
4. **本地存储**：保存稳定标识、元信息快照、用户设置及播放进度。
5. **平台适配层**：封装媒体快捷键、系统媒体会话和后台运行等平台差异。

前端通过受限的 Tauri Commands 调用原生能力。网络请求仅面向允许的内容源与必要的媒体域名，不提供可任意访问 URL 的通用代理。

### 媒体解析与播放

1. 解析用户输入，取得视频及分 P 的稳定标识。
2. 读取元信息，检查当前访问条件及可用媒体格式。
3. 优先验证独立音频流能否在目标平台稳定播放；音频模式只加载音频时，才有节省视频流量的效果。
4. 打开视频时，取得对应视频资源，在当前音频时间点定位并完成同步。
5. 收起视频时释放不再需要的视频资源，同时保持音频连续播放。
6. 临时媒体地址失效时，根据稳定标识重新解析，并尽可能恢复当前进度；重试次数有限。

不能假定一个视频地址可直接交给 `<video>` 播放。若平台提供分离的音视频轨，需要选择支持该形式的播放方案，并处理缓冲、拖动进度和同步。具体使用原生媒体能力还是 MSE，应由第一阶段验证结果决定。

遇到 WebView 的跨域、请求头或格式限制时，先验证合规的原生请求和媒体传输方案；若确有必要，再评估受限的本地媒体代理，并验证 Range 请求、资源释放和安全边界。不能仅靠隐藏视频画面来宣称实现了纯音频传输。

### 音视频切换

- 以统一播放状态为准，记录当前曲目、目标进度、暂停状态和音量。
- 展开视频时，在资源准备完成后定位到当前播放点，避免重复播放两路音频。
- 暂停状态下切换模式，仍保持暂停；视频加载失败时，尽可能继续原有音频播放。
- 对加载、切歌和切换模式使用可取消的操作，防止旧请求覆盖新曲目。
- 验证连续切换、拖动进度、缓冲和切歌时的同步表现，不预先承诺无缝切换。

### 数据与隐私

- 队列项包含视频标识、分 P 标识、标题、作者、封面和时长等信息。
- 临时媒体地址按需获取，不写入长期记录或日志。
- 首版不要求账号登录；如后续需要登录，应由用户主动授权，敏感凭据交给系统安全存储，避免明文写入普通配置。
- 对平台请求设置超时、有限重试与并发限制，不进行批量抓取。

## 实施阶段与验收

### 阶段一：验证播放可行性 ✅ 基本完成

在 Windows 上选取有权访问的普通视频和多分 P 视频，验证元信息读取、媒体地址有效期、音频播放、视频播放和进度定位。

验收重点：独立音频是否可用、实际加载了哪些资源、WebView 编解码兼容性，以及音视频切换方案是否成立。这一阶段决定后续媒体引擎的选择。

实测结论：独立音频流匿名可用（DASH 三档 AAC），WebView2 播放 fMP4/AAC 正常；WAF 按请求形态拦截（详见 [M0 技术验证记录](docs/m0-findings.md) §2.1）；签名媒体地址有效期很短，"每次播放前重新解析"成为既定架构。音视频切换尚未验证。

### 阶段二：完成最小播放器 🔶 基本完成

实现链接添加、分 P 选择、播放队列、基础控制、循环模式和视频切换。

验收重点：从添加内容到完整播放的路径可用；切换模式后曲目和进度一致；没有双重音频；切歌、暂停和拖动进度行为正确。

音频路径已实机跑通（含多分 P 与合集），本地持久化（队列 / 进度 / 音量 / 模式）已就绪；音视频切换按 2026-09-18 调整移至阶段四，与账号登录同期实现。

### 阶段三：完善持久化与异常处理

增加设置和播放记录保存、媒体地址刷新、网络错误处理和内容失效提示。

验收重点：重启可恢复记录；断网或地址过期不会使应用卡死；失效内容可以重试、移除或跳过。

队列/进度/音量的重启恢复已实现（快照方式）；地址过期与错误的提示已具备基础版本。

### 阶段四：扩展平台与体验

音视频切换与账号能力（扫码登录、收藏同步）在本阶段一起实现——视频观看受登录状态限制，登录后统一放开。此外验证 macOS / Linux，增加歌单、系统媒体控制等能力，再评估移动端适配。

验收重点：按平台检查格式支持、后台行为、资源占用和打包结果，不以单个平台的成功替代跨平台验证。

## 当前进度

截至 2026-09-18（main 分支），桌面端已实现：

- **内容添加**：粘贴链接或 BV 号 → 解析元信息（标题 / UP 主 / 封面 / 时长）；多分 P 与合集（ugc_season）双 Tab 选择，支持全选 / 清空，合集条目带各自封面、时长、UP 主。
- **音频播放**：DASH 独立音轨，按码率自动选档；经本地代理拉流（注册表模式：只转发解析登记过的地址；官方 CDN 镜像优先、失败自动轮替；开放式 Range 切成有界分块）。
- **播放控制**：播放 / 暂停、上一首 / 下一首、拖动进度、音量（含百分比显示）、顺序 / 单曲循环 / 列表循环 / 随机四种模式。
- **队列管理**：当前项标记（跳动条动画）、点击播放、移除、清空、上移 / 下移。
- **持久化**：队列、循环模式、音量、播放进度的本地快照（进度类每 2 秒节流落盘，增删与播放状态变化立即写入），重启后恢复队列，点播放从记录进度继续。
- **界面**：深色主题（B 站粉 + 紫渐变强调色），BM 应用图标。
- **测试**：Rust 解析链路实网冒烟测试（`cargo test --test live_parse`，依赖外网）。

尚未实现：音视频切换（计划与账号登录一起实现）、本地歌单、账号登录与收藏同步、系统媒体控制、macOS / Linux 适配。

## 运行

```bash
npm install
npm run tauri dev
```

要求 Node 18+、Rust 工具链、Windows 10+（WebView2）。打包：`npm run tauri build`。

## 下载安装

到 [Releases](https://github.com/roy2651/bMuisc/releases) 下载对应平台的安装包：

| 平台 | 文件 | 说明 |
| --- | --- | --- |
| Windows 10+ | `*-x64-setup.exe` | 直接运行安装 |
| macOS（Apple Silicon） | `*-aarch64.dmg` | M 系列芯片 |
| macOS（Intel） | `*-x64.dmg` | Intel 芯片 |

**macOS 首次打开说明**：安装包未做 Apple 公证（无开发者账号），首次打开会被系统拦截。按以下任一方式放行：

1. **系统设置 → 隐私与安全性**：先尝试打开应用一次，被拦截后进入该设置页，滚到底部会提示「已阻止…因为来自身份不明的开发者」，点击**「仍要打开」**即可（推荐，各版本系统通用）；
2. 终端执行：`xattr -cr /Applications/bMuisc.app`（清除隔离标记，若提示「应用已损坏」用这条解决）；
3. 较旧系统（macOS 13/14）也可在访达中**右键点击应用 → 打开 → 再点「打开」**。

## 主要约束

- B 站接口、访问要求和媒体地址策略可能变化，内容源适配器需要持续维护。
- 免费观看不代表允许下载、转存或再分发；应用仅处理用户有权访问、且平台规则允许使用的内容，不绕过登录、付费或内容保护机制。
- 本项目为独立项目，与 B站无官方关联；内容权利归原作者及相关权利人所有。
- 在确认媒体访问方式和使用条件可行后，再投入完整工程开发。
