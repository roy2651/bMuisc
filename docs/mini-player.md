# 迷你播放器需求与验收

> 2026-10-08 确认需求；2026-10-09 已随 v0.5.0 实现（Windows v1，入口仅 Windows 显示；macOS 单独验证后再开放）。本次已整理工程验证与实机记录边界，详见 §8 和 [v0.5.0 收尾记录](reviews/2026-10-09-v050-closeout.md)。
>
> 用户确认：需要类似桌面音乐软件的迷你播放器，在使用其他应用时快速切歌、暂停、点红心。该优先项现已实现；主窗口窄窗导航和队列遮挡优化保留后续待办。

## 1. 用户场景与目标

用户边工作边听歌，主窗口无需一直占据桌面。一个可常驻的小浮窗显示正在播放的内容，提供一步可达的上一首、播放 / 暂停、下一首、加入 / 取消喜欢；需要找歌、管理歌单时再回到主窗口。

迷你播放器是独立的播放控制入口，不等同于把现有主窗口缩小，也不替代主窗口的导航和队列功能。托盘与系统媒体控制继续作为补充入口。

## 2. 首版范围与优先级

“必备”是本次确认的核心需求；其余为落地建议，视觉稿和原生可行性验证后再确定细节，不把建议写成用户已逐项批准。

| 优先级 | 内容 | 边界 |
| --- | --- | --- |
| 必备 | 上一首、播放 / 暂停、下一首、红心 | 常驻可见，一次点击即可操作；复用现有播放模式和喜欢语义 |
| 必备 | 当前曲目与状态 | 封面、曲名、是否喜欢、播放 / 暂停 / 加载 / 错误状态；分 P 标题沿用现有规则 |
| 首版建议 | 进入迷你模式、展开主窗口、关闭浮窗 | 明确区分隐藏浮窗与退出应用；切换窗口不断音、不重新点播 |
| 首版建议 | 拖动、置顶、位置恢复 | 默认置顶，可取消；记住位置，屏幕变化后仍可找回 |
| 可选增强 | 进度显示 / 拖动、音量浮层、播放模式切换 | 先保证核心按钮空间；不作为第一版核心四键的前置条件 |
| 后续 | 浮窗内展开队列、歌词、皮肤、边缘吸附 | 暂不进入首版 |

主窗口导航、队列遮挡优化保留为独立待办；本轮不同时扩展为整体 UI 改版。Windows 为首要实现与验收平台；macOS 单独验证焦点和窗口生命周期后再开放，Linux 暂不纳入本轮。

## 3. 布局建议

- 沿用项目深色与粉色强调色，采用紧凑横向卡片。约 340×90 逻辑像素作为效果稿起点，最终尺寸以四个核心按钮、窗口操作和缩放下的可点击性为准。
- 左侧封面，旁边展示曲名；长标题省略并提供完整标题提示。UP 主可作次要信息，不能挤掉核心操作。
- 上一首、播放 / 暂停、下一首、红心始终可见，不能仅靠悬停出现；播放 / 暂停为主要按钮，红心明确区分已喜欢与未喜欢。
- 置顶、展开主窗口、关闭浮窗作为次级窗口操作，提供名称或提示。拖动使用独立空白区域，按钮区域不得触发窗口拖动。
- 加载提示不替代暂停能力：加载中仍能表达暂停意图和切歌；错误状态显示简短原因并提供重试或返回主窗口处理入口。

## 4. 当前交互与原设计差异

以下记录 v0.5.0 的实际行为，不代表所有设计建议均已采用。与原建议存在的差异保留为待确认项。

| 项目 | 原建议 | v0.5.0 当前行为 |
| --- | --- | --- |
| 进入入口 | 底部播放栏 | Windows 顶栏按钮和托盘菜单 |
| 浮窗 X | 只隐藏浮窗，继续后台播放 | 与展开按钮一样返回主窗口；系统 CloseRequested 则只隐藏窗口。X 的语义与提示仍需产品确认 |
| 弹窗期间进入 | 禁用切换并提示 | 没有统一的弹窗阻止逻辑，托盘仍可发起切换；是否增加保护保留待办 |
| 焦点与键盘 | 尽量少打断其他应用，同时键盘可达 | 配置 `focusable(false)`，完整键盘可达性未验收 |

1. **进入**：Windows 顶栏与托盘提供“迷你播放器”入口。先登记可取消请求，再初始化监听、创建或复用隐藏浮窗；完成位置与状态同步后显示浮窗并隐藏主窗口。五秒期限覆盖初始化和建窗等待，超时 / 取消后迟到结果不能重新提交。
2. **使用**：浮窗直接控制当前播放会话。上下曲遵循主播放器现有模式；播放 / 暂停、红心的实际结果由主播放控制器回传，不只改变浮窗图标。
3. **红心**：操作针对用户点击时看到的曲目，按 `bvid:cid` 更新“我的喜欢”；不重排队列、不重播、不触发 B 站收藏推送。连续切歌时不能把上一首的红心指令应用到新曲目。
4. **展开**：显示并聚焦原主窗口，恢复进入前的浏览页面，收起浮窗；不重新建立队列、不重置播放进度。
5. **收起与退出**：当前浮窗 X 返回主窗口并继续播放；Windows 系统关窗只隐藏对应窗口。托盘同时提供“显示主窗口”“迷你播放器”和“退出”。原建议的 X 仅隐藏行为尚未采用，参见上表。
6. **再次唤起**：托盘“显示主窗口”或已有单实例唤起路径应能恢复主窗口并收起浮窗，避免失去控制入口。重复点击迷你入口只复用同一个浮窗。
7. **重启**：保留现有“不自动播放”约定。当前启动时显示主窗口、预建隐藏浮窗，仅在主动进入时恢复浮窗位置和置顶偏好，不自动弹出浮窗。

拖动时不能改变进度或触发按钮。恢复位置时按当前显示器工作区和 DPI 校正，覆盖外接屏拔除、分辨率改变和缩放改变。

## 5. 状态与边界

| 场景 | 预期行为 |
| --- | --- |
| 队列为空 | 显示“暂无播放内容”，禁用无目标的切歌和红心，提供展开主窗口入口 |
| 已恢复队列但未播放 | 展示恢复状态，用户点播放才开始；进入浮窗本身不能自动播放 |
| 解析 / 缓冲中暂停 | 保留最新暂停意图，迟到解析结果不自行出声；显示加载与暂停意图的区别 |
| 连续切歌、自然播完切歌 | 曲名、封面、播放态、红心保持同一曲目版本，旧状态不能覆盖新曲目 |
| 点击红心与切歌交错 | 只作用于点击时显示的曲目；目标不存在时刷新状态并说明，不误改另一首 |
| 播放失败 | 可重试当前曲目或切到下一首；恢复状态与主窗口一致 |
| 状态通道暂不可用 | 显示连接 / 同步状态，禁用依赖当前曲目的操作；不假装成功或重放过期指令 |
| 浮窗重建 / 反复开关 | 获取最新完整状态，无重复监听、重复执行指令、第二路声音或收藏快照丢失 |
| 设置 / 解析等弹窗打开时进入迷你模式 | 首版建议禁用模式切换并给出提示，避免把未完成的确认或输入隐藏；恢复主窗口时保留既有输入 |
| 后台自动更新提示 | 不静默安装；用户应能通过可见提示回到主窗口处理，不因隐藏主窗丢失操作入口 |
| 退出应用 | 按现有路径保存有效状态并退出所有窗口，不能由空副窗覆盖主快照 |

## 6. 实现约束与待验证项

当前采用独立 Tauri `mini` 窗口作为遥控界面，主窗口隐藏后继续承载播放。已实现 requestId 关联的登记 / 取消 / 提交与原生过期检查；平台差异与真实资源占用仍按专项清单记录，历史估值不视为实测。

- **唯一播放控制器与快照写者**：主窗口的 store / engine 继续管理媒体、队列、喜欢和快照。副窗不启动第二个媒体引擎，不恢复或写入 `bmuisc.snapshot.v3`，不注册退出落盘，不独立接管系统媒体控制。
- **独立副窗入口**：不能只靠隐藏主 App 的 UI 达成隔离；需保证副窗导入链没有主 store 的持久化或引擎初始化副作用。
- **状态同步**：副窗先订阅，再请求完整状态；后续由主窗口发布带版本信息的状态更新，丢弃旧状态。广播只包含展示与控制必需的信息，不发送完整曲库、登录凭证或签名媒体地址。
- **指令处理**：副窗发送受限操作，主窗口统一执行并回传结果。红心等曲目相关操作携带稳定目标标识；重复监听和重连不能造成一次点击执行多次，失败不得显示成功。
- **窗口生命周期**：隐藏主窗口不能卸载播放引擎。进入失败须回退，退出应用须处理全部窗口。仅为 `mini` 配置必要权限，并校验可接受的命令来源和参数。
- **偏好存储**：浮窗位置与置顶偏好单独存储，由一个明确的宿主写入，不引入播放快照的第二写者。
- **焦点与键盘**：目标是尽量少打断正在使用的应用，同时提供完整的按钮名称、焦点提示和键盘可达性。Windows 不激活窗口方案与键盘操作的兼容性须验证，不能直接照搬历史 `focusable:false` 配置并声称键盘可用；macOS 单独验证首次点击和切换应用行为。
