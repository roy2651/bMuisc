# 原视频跳转（「在B站看视频」）需求与设计

[返回 README](../README.md) · [产品规划](project-plan.md)

2026-10-16 定稿（同日两步决定）。用户决定：**不做应用内音视频解码切换**（原 M4 的 DASH + MSE 方向撤销），视频需求由本项承接——想看画面时暂停本地音乐、打开 B 站网页，先以**系统浏览器跳转**落地（本文 §1–§8，已实现）；M4 升级为**应用内视频窗口**（窗口加载 B 站网页、关闭后恢复音频播放，方向见 §9）。两种形态下登录态、清晰度、会员内容、弹幕都由 B 站网页自行处理，应用不介入也不绕过。

## 1. 用户场景

1. **核心**：正在听多 P 内容的第 8 集、已播到 3:45，想看画面 → 点底栏「看视频」→ 本地音乐暂停，浏览器打开该视频 P8 的 3:45 处；回到应用点播放，从 3:45 继续。
2. **列表跳转**：浏览列表时想看某首（未必在播）→ 行菜单「在B站看视频」→ 若当前有播放则暂停，浏览器打开该曲对应分 P 开头。
3. **正在播放卡片**：大卡片入口与上同款行为（原「打开原页面」升级）。

## 2. 入口

| 入口 | 位置 | 跳转目标 | 可用条件 |
| --- | --- | --- | --- |
| 「看视频」按钮（新增） | 底栏播放条 `.pb-volume`，队列按钮旁 | 当前播放曲 | 有当前曲（含加载 / 错误态），否则禁用 |
| 「在B站看视频」 | 正在播放大卡片（原「打开原页面」改文案） | 当前播放曲 | 有当前曲 |
| 行菜单项 | 列表行 ⋯ 菜单 | 该行曲目 | 任意行（含未播放） |

迷你浮窗 v1 不加入口（主窗先行）；主窗隐藏时需先展开主窗。

## 3. 行为与 URL 规则

三处入口统一走独立模块 `src/videoJump.ts` 的 `jumpToVideo(item)`（miniHost 先例：编排 store 动作，不进 store，避免 `plugin-opener` 新依赖破坏回归脚手架）：

1. **防抖**：距上次跳转 <800ms 的重复点击直接忽略（防连点多开标签页）。
2. **构造 URL**：`https://www.bilibili.com/video/{bvid}/`，按需追加：
   - `?p={page}`：仅当曲目带分 P 序号且 >1（P1 为默认页省略；合集单集是独立 BV 号，天然不需要）。
   - `&t={秒}`：仅当跳转目标是当前播放曲且进度 ≥5 秒，取整秒；跳非当前曲不带 `t`（它没有进度概念）。
3. **打开浏览器**：`openUrl(url)`；**成功后**若当前有播放（含解析 / 缓冲中，无论跳转目标是否为当前曲）且播放意图未被替代，执行 `store.pause()`。顺序必须是先开后停——`openUrl` 失败时音乐不受影响。等待期间用户切歌 / 重播 / 手动播放暂停的，过期回调不再暂停（`intentSeq` 播放意图版本守卫，见 §4）；自然结束的自动接续不算新意图，暂停仍然生效。
4. **失败反馈**：`openUrl` 拒绝（如系统无默认浏览器）→ `notify` 提示，不暂停。

暂停走显式意图入口，与媒体键 / 错误重试同一路径；解析 / 缓冲期间跳转，解析完成后不会意外出声（v0.5.1 修复路径已覆盖）。

## 4. 数据变更

- `Track` 增加可选字段 `page?: number`（分 P 序号）：解析弹窗（ParseModal）与收藏导入（FavImportModal）构建多 P 条目时从 `PageInfo.page` 带入；合集单集不设。
- 曲库物化 / 元信息刷新路径（store.ts lib 拷贝）透传 `page`，其余字段不变。队列里的同名副本以曲库最终条目为准同步刷新（保留条目 ID 与播放进度——底栏 / 正在播放卡片读的是队列对象），**副本是否落后独立于曲库是否变化判断**（库没变但队列仍旧——如撤销清空带回的旧副本——也要补齐）；`page` 缺省不回写，红心重喂旧队列对象不得抹掉已补齐的序号。撤销清空（undoClear）恢复时按 `bvid:cid` 合并最新曲库元数据（备份存续期间库可能已被重新解析刷新），队列 ID、顺序与播放状态保持备份原样。
- store 新增 `intentSeq` 播放意图版本（用户播放控制操作递增，不落盘、不进快照）：跳转的延迟暂停据此丢弃过期回调。
- 快照 v3：可选字段天然兼容，**无版本号变更、无迁移**；旧条目缺 `page` 时退化为不带 `p` 参数（打开 P1，与现状一致）。
- `mini:state` 协议不变（浮窗无跳转入口，不需要 `page`）。

## 5. 边界与失败状态

| 状态 | 行为 |
| --- | --- |
| 旧快照条目无 `page` | 不带 `p`，打开 P1（可接受降级，不破坏恢复） |
| 加载中 / 解析中点跳转 | 照常跳转 + 暂停意图生效，解析完成后不出声 |
| 当前曲处于 error 态 | 按钮可用（跳转只依赖元信息，不依赖媒体流） |
| 无当前曲 | 底栏按钮禁用；行菜单仍可跳（仅开浏览器，无暂停动作） |
| `openUrl` 失败 | notify 提示，音乐不受影响 |
| 800ms 内连点 | 合并为一次 |
| 跳转等待期间切歌 / 重播 / 手动播放暂停 | 过期回调不再暂停，以最新播放意图为准 |
| 跳转等待期间自然结束自动接续 | 接续不是新意图，回调到达后仍暂停（看视频时音乐停） |
| 清空队列 → 撤销窗口内补齐 `page` → 撤销清空 | 撤销恢复合并最新曲库元数据（保留队列 ID / 顺序），跳转仍带正确 `p` |
| 迷你模式（主窗隐藏） | 无入口，需先展开主窗（v1 已知限制） |

## 9. M4 方向：应用内视频窗口（2026-10-16 已定，启动时再细化设计）

用户进一步决定（同日第二项）：「在应用打开网页播放视频，音频暂停，关闭视频就回到音频播放」。本功能在 M4 从系统浏览器升级为**应用内视频窗口**——Tauri 子窗口加载 B 站网页，当前浏览器跳转是过渡形态。

### 行为轮廓

1. **打开**：单窗口复用（已开则同窗口导航到新地址，防抖沿用）；窗口建立成功后暂停音频，沿用「先开后停」与显式意图入口（解析 / 缓冲期同样安全）。
2. **关闭恢复**：关闭视频窗口 → 本地音频从暂停点恢复播放。恢复条件：**仅当暂停是打开视频窗口造成的，且窗口存续期间没有更新的手动意图**（手动暂停 / 切歌 / 主动播放）——关闭窗口不得覆盖用户最新意图（与删除当前项、错误重试同一原则）。跳非当前曲时同样恢复当前曲。
3. **窗口内导航**：允许 B 站页内正常跳转（点开相关视频等）；关闭恢复的始终是本地音频，与窗口里最后看的内容无关。

### 与当前实现的关系

入口、`Track.page`、`videoUrl()` 规则、防抖、失败反馈全部复用；M4 只把打开目标从系统浏览器换成应用内窗口，并新增关闭恢复语义（`verify-jump` 相应用例同步扩展）。

### 待验证 / 待决策（M4 启动时）

- **登录态**：SESSDATA 只进 keyring，不注入 webview（凭证不进前端红线）；匿名清晰度上限与音频现状一致，需要更高清晰度由用户在窗口内登录 B 站，webview cookie 持久化行为需实测。
- **窗口工程**：子窗 capabilities 单独配置（mini 先例）；建窗走 async 命令 / 独立线程（wry#583 同款约束）；窗口尺寸 / 位置持久化（同 mini 几何思路）；WebView2（Chromium）预期兼容，macOS WebKit 单独验收。
- **失败状态**：webview 加载失败（断网）窗口内提示与重试；音频保持暂停，由用户手动恢复。
- **入口互斥**：迷你模式（主窗隐藏）无入口，沿用现状。

### 验收轮廓（M4）

- 打开窗口：音频暂停、窗口加载对应分 P 与进度；关闭窗口：音频从原进度恢复
- 窗口期间手动暂停 → 关闭不自动恢复；窗口期间切歌 → 关闭恢复到最新当前曲的正确状态
- 跳非当前曲：窗口开该曲对应分 P 开头，关闭恢复当前曲
- 窗口内导航到其他视频后关闭，恢复的仍是本地音频
- 已开窗口时再次跳转 = 同窗口导航，不开新窗
- 断网 / 加载失败有反馈，不双重出声；重启不自动开窗
