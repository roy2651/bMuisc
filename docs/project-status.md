## 实施阶段与验收

### 阶段一：验证播放可行性 ✅ 完成

在 Windows 上选取普通视频和多分 P 内容，验证元信息、媒体地址、独立音频及进度定位。应用内音视频切换已于 2026-10-16 撤销，视频需求由原视频跳转承接。

验收重点：独立音频是否可用、实际传输资源及 WebView 编解码兼容性；已据此确定 HTMLAudioElement 与本地代理方案。

实测结论：独立音频流匿名可用（DASH 三档 AAC），WebView2 播放 fMP4/AAC 正常；WAF 按请求形态拦截（详见 [M0 技术验证记录](m0-findings.md) §2.1）；签名媒体地址有效期很短，"每次播放前重新解析"成为既定架构。应用内解码播放已撤销；视频由网页承接（当前浏览器跳转，M4 应用内视频窗口）。

### 阶段二：完成最小播放器 ✅ 完成

实现链接添加、分 P / 合集选择、播放队列、基础控制、循环模式和本地恢复。

验收重点：从添加内容到完整音频播放的路径可用；切歌、暂停、定位和重启恢复行为正确。

音频路径已实机跑通（含多分 P 与合集），本地持久化（队列 / 进度 / 音量 / 模式）已就绪；音视频切换已于 2026-10-16 撤销，视频需求由网页承接（M4 应用内视频窗口；账号登录已随 v0.4.0 实现）。

### 阶段三：完善持久化与异常处理 🔶 进行中

增加设置和播放记录保存、媒体地址刷新、网络错误处理和内容失效提示。

验收重点：重启可恢复记录；断网或地址过期不会使应用卡死；失效内容可以重试、移除或跳过。

快照 v3、坏档备份与旧版恢复、失败音源重试、会话隔离、暂停意图、预取回退、代理异常处理、最近播放及封面缩略图内存优化已实现并完成针对性复审；设置页与自动更新已随 v0.3.0 交付。2026-10-14 补齐异常矩阵的代码级与实网级证据（隔离探针 + 真实 B 站请求，含错误重试意图、-400 双关提示与 -404 失效映射修复，见 [规划 M3 进展](project-plan.md)），桌面 UI 层实机触发仍待补。

### 阶段四：扩展平台与体验 🔶 部分提前完成

本地音乐库、喜欢和歌单已提前完成；账号登录与收藏双向同步随 v0.4.0 实现，系统媒体控制随 v0.3.2 实现；macOS 基础音频流程已有历史实机记录。应用内视频解码播放已撤销（2026-10-16），原视频跳转（浏览器）已实现，应用内视频窗口列为 M4 任务；Linux 与移动端适配仍未实现。

验收重点：按平台检查格式支持、后台行为、资源占用和打包结果，不以单个平台的成功替代跨平台验证。
